# 🧭 C# Developer Career Progression Roadmap

## And How Your Learning Should Evolve at Each Stage

Think of your career like Drag Race seasons:

* **Junior**: Learn the rules
* **Mid-level**: Make good choices
* **Senior**: Make others better

Your **learning roadmap changes at every stage**.

---

## 🍼 Stage 1: Junior C# Developer (0–2 years)

### 🎯 Career Goal

> “I can be trusted with tasks without breaking production.”

You are paid to **learn fast, not to redesign the system**.

---

### 🧠 What the Job Expects

* Write working C# code
* Understand OOP basics
* Follow existing architecture
* Fix bugs without panic
* Ask good questions

No one expects you to be clever.
They expect you to be **reliable**.

---

### 📚 Learning Roadmap (Junior)

**Primary Focus**

* C# syntax & fundamentals
* OOP concepts
* Collections & LINQ basics
* Debugging

**Resources**

* Tim Corey: C# Fundamentals, OOP
* Microsoft Learn: C# & .NET basics
* Exercism: C# Track

**How to Study**

* Learn → practice → build tiny things
* Rewatch fundamentals (yes, again)
* Don’t chase frameworks yet

📌 *Junior mistake*: jumping to “advanced” topics too early
📌 *Junior win*: mastering basics until boring

---

## 🔄 Transition Phase: Junior → Mid-Level

This is the **hardest jump**. Not technical. Mental.

You must stop thinking:

> “Tell me what to code”

And start thinking:

> “Why is this designed this way?”

---

### 🚧 What Blocks People Here

* Shallow understanding of OOP
* Copy-paste LINQ
* Fear of touching existing code
* Over-reliance on seniors

This is where many get stuck for **years**.

---

## 🧑‍💻 Stage 2: Mid-Level C# Developer (2–5 years)

### 🎯 Career Goal

> “I can own features and make technical decisions.”

You are no longer just implementing.
You are **choosing approaches**.

---

### 🧠 What the Job Expects

* Design small components
* Use interfaces & DI properly
* Write async code safely
* Refactor legacy code
* Review junior code
* Explain trade-offs to others

If something breaks, people expect **you** to fix it.

---

### 📚 Learning Roadmap (Mid-Level)

**Primary Focus**

* SOLID principles
* Dependency Injection
* Async / Await
* Design Patterns (practical)
* Clean Code

**Resources**

* Tim Corey: DI, Clean Code, Patterns
* Microsoft Learn: Async & Performance
* Refactoring Guru
* Nick Chapsas (free YouTube)

**How to Study**

* Refactor old projects
* Read real codebases
* Learn *when not to apply patterns*

📌 *Mid-level mistake*: overengineering
📌 *Mid-level win*: simple, maintainable solutions

---

## 🧠 How Learning Changes at Mid-Level

| Junior Learning       | Mid-Level Learning   |
| --------------------- | -------------------- |
| “How does this work?” | “Why this approach?” |
| Tutorials             | Documentation & code |
| Small exercises       | Real projects        |
| Syntax                | Trade-offs           |

This is where **Tim Corey suddenly makes more sense**. That’s normal.

---

## 🧓 Stage 3: Senior C# Developer (5+ years)

(I know you didn’t ask, but I’m your gay best friend, I plan ahead.)

### 🎯 Career Goal

> “The team is better because I’m here.”

---

### 🧠 What the Job Expects

* System-level thinking
* Architectural decisions
* Mentoring
* Risk management
* Performance & scalability awareness

Less typing. More thinking.

---

### 📚 Learning Roadmap (Senior)

* System design
* Performance tuning
* Architecture patterns
* Cloud & deployment concepts
* Communication skills (very underrated)

Learning now comes from:

* Reading proposals
* Reviewing designs
* Teaching others

---

## 🧠 One Big Truth (Listen Carefully)

> **Career progression is not about learning MORE.
> It’s about learning the RIGHT THINGS at the RIGHT TIME.**

Junior hoards knowledge.
Mid-level applies knowledge.
Senior filters knowledge.

---

## 🗺️ How to Use This Roadmap Practically

### Weekly Study Rule (Singapore realistic version)

* 1–2 hours per weekday
* 1 small project every 4–6 weeks
* Revisit fundamentals every few months

### Promotion Readiness Check

Ask yourself:

* Can I explain my code?
* Can I fix bugs confidently?
* Can I review others’ code?
* Can I justify my design choices?

If yes, you’re already acting at the next level.

---

## TL;DR (Busy MRT Edition 🚇)

* **Junior**: Learn fundamentals, follow patterns
* **Mid-level**: Make decisions, refactor, explain trade-offs
* **Senior**: Design systems, mentor, think long-term

**Tim Corey** = foundation + mindset
**Free resources** = reinforcement, exposure, modern practices
